2. SOBRE A "API" / QUEDA NO RENDER  (LEIA)
---------------------------------------------------------------------
O QUE EU ENCONTREI
- Este projeto NAO tem backend/API. E so um front-end (Vite + React).
  Nao existe nenhum fetch/axios/rota, nem arquivo server.js, e a pasta
  nao e um repositorio git. Os dados ficam no localStorage do
  navegador de cada visitante.
- Por isso eu nao consigo ver o que caiu no Render: nao tenho acesso
  ao painel nem aos logs, e se existe uma API, ela nao esta nesta pasta.
  >>> Se a API e outro projeto, me mande o LOG de erro do Render
  >>> (aba "Logs") e o codigo dela que eu investigo de verdade.

CAUSAS PROVAVEIS QUE EU CORRIGI NESTE PROJETO
Se voce publicou ESTE projeto como "Web Service" no Render, ele
provavelmente falhava por um destes motivos:

  a) Nao existia o script "start" no package.json.
     Render roda "npm start" e dava "Missing script: start".
     -> CORRIGIDO: "start": "vite preview".

  b) O "vite preview" bloqueia dominios desconhecidos e responde
     "Blocked request. This host is not allowed" no endereco
     *.onrender.com.
     -> CORRIGIDO em vite.config.ts: preview.allowedHosts = true.

  c) O Render informa a porta pela variavel de ambiente PORT, e o
     preview ouvia so na porta padrao.
     -> CORRIGIDO em vite.config.ts: usa process.env.PORT e host
        0.0.0.0.

  d) Dependencias de build estavam em devDependencies. O Render usa
     NODE_ENV=production e pode pular devDependencies, quebrando o
     build (o "tailwindcss" estava la; o "vite" aparecia duplicado).
     -> CORRIGIDO: tailwindcss movido para dependencies e vite
        deixou de ser duplicado.

  e) Havia pacotes de servidor sem uso (express, dotenv,
     @google/genai, motion) deixando o build mais pesado/lento.
     -> REMOVIDOS (nenhum era importado no codigo).

COMO PUBLICAR NO RENDER (2 opcoes - a 1 e a mais indicada)
  Opcao 1 - Static Site (recomendada, gratis e sem "queda"):
     Build Command:      npm install && npm run build
     Publish Directory:  dist
  Opcao 2 - Web Service:
     Build Command:      npm install && npm run build
     Start Command:      npm start
  Node: use versao 20 ou maior (package.json agora exige >=20).

IMPORTANTE (limitacao real do projeto)
  Como nao ha backend, os anuncios que alguem publica so aparecem
  NAQUELE navegador. Outras pessoas nao veem. Para um marketplace de
  verdade (todos vendo os mesmos anuncios) e preciso criar uma API +
  banco de dados. Posso ajudar nisso como proximo passo - e ai sim
  teria uma API para hospedar no Render.

3. BUGS CORRIGIDOS (os 6 do relatorio anterior)
---------------------------------------------------------------------
[1] Contador da categoria "Doacao" aparecia dobrado
    Antes : src/App.tsx (categoryCounts) somava a doacao duas vezes
            (pela flag isDonation E pela categoria 'Doacao').
    Agora : "Doacao" deixou de ser categoria. Conta so pela flag
            isDonation. Uma doacao tambem conta na categoria real
            dela (ex.: livro doado conta em "Livros & Apostilas").
    Onde  : src/lib/items.ts -> countByCategory()

[2] "Mais recentes" nao colocava itens novos no topo
    Antes : ordenava por id.localeCompare (texto). Item novo ficava
            abaixo do item-8 dos exemplos.
    Agora : cada anuncio tem publishedAt (data em milissegundos) e a
            ordenacao usa esse numero. Empates de preco/popularidade
            sao desempatados pelo mais recente.
    Onde  : src/types.ts (publishedAt), src/lib/items.ts -> sortItems()

[3] WhatsApp do vendedor vinha com numero de outra pessoa
    Antes : campo ja vinha preenchido com 5585999887766 (numero da
            Mariana, dos exemplos). Numero sem "55" gerava link invalido.
    Agora : campo comeca vazio, e obrigatorio e validado. "85999887766"
            e "(85) 99988-7766" viram 5585999887766 automaticamente.
            Seus dados (nome/curso/WhatsApp) sao lembrados para os
            proximos anuncios.
            Se um anuncio antigo tiver numero invalido, o botao mostra
            um aviso em vez de abrir um link quebrado.
    Onde  : src/lib/whatsapp.ts, src/lib/newItemForm.ts,
            src/components/NewItemModal.tsx

[4] Formulario "Desapegar": categoria "Doacao" presa e preco vazio
    Antes : desmarcar Doacao deixava a categoria como "Doacao";
            preco vazio virava doacao sem avisar; aceitava preco
            negativo; URL de imagem sem validacao.
    Agora : categoria e estado sao escolhas reais e independentes da
            doacao. Preco e obrigatorio (> 0) se nao for doacao. URL
            da imagem precisa ser http/https. Erros aparecem abaixo de
            cada campo, em portugues.
    Onde  : src/lib/newItemForm.ts, src/components/NewItemModal.tsx

[5] Filtros de doacao / favoritos / categoria entravam em conflito
    Antes : existiam DOIS estados para doacao (onlyDonations e a
            categoria "Doacao"), dessincronizados. Ex.: desligar o
            botao "Doacoes" nao limpava a categoria; aba "Salvos" do
            celular mostrava so doacoes salvas.
    Agora : um unico objeto de filtros. "Doacao" e simplesmente um
            valor de category. Header, chips, banner e menu mobile
            leem e escrevem o mesmo estado, entao nao ha como
            divergir. Favoritos + doacoes podem ser combinados.
    Onde  : src/hooks/useMarketplaceFilters.ts, src/lib/items.ts,
            src/App.tsx

[6] App podia quebrar com dados ruins no localStorage
    Antes : JSON.parse sem validacao ("null" ou formato estranho
            derrubava a tela); itens de exemplo ficavam "congelados" no
            navegador; erro de cota nao era tratado.
    Agora : toda leitura e protegida e validada (src/lib/storage.ts e
            src/lib/itemStorage.ts). So os anuncios DO USUARIO sao
            salvos; os de exemplo vem do codigo (se voce editar o
            mockItems.ts, todo mundo ve a mudanca).
            Dados antigos sao migrados automaticamente (secao 6).

4. PROBLEMAS MENORES CORRIGIDOS
---------------------------------------------------------------------
- Hooks depois de "return null" nos 3 modais (violava as regras do
  React). Agora o App so renderiza o modal enquanto ele esta aberto.
- Toast: efeito colateral dentro do setState (rodava 2x no StrictMode)
  e timer que apagava o toast novo. Agora e o hook useToast.
- Compartilhar: copiava so a URL da pagina e quebrava em http://.
  Agora usa o compartilhar nativo do celular ou copia
  "titulo - preco (local) + link", com tratamento de erro.
- Modais: agora fecham com Esc, travam o scroll da pagina, focam ao
  abrir e tem aria-label. Clicar fora fecha, exceto no formulario
  (para nao perder o que foi digitado).
- Imagens: itens sem foto ou com link quebrado usam imagem padrao
  (componente SafeImage). Antes a lista e o detalhe quebravam.
- Avatar: o nome na URL do dicebear agora e codificado (acentos).
- CSS: criado o breakpoint "xs" (o texto "Doacoes" do header e o
  "WhatsApp" da lista nunca apareciam) e as animacoes fadeIn/scaleUp
  que nao existiam.
- Barra de categorias com altura fixa (top-[100px]) removida. Header
  e categorias agora ficam juntos num unico bloco "sticky".
- Chip de filtro de "estado" agora aparece nos filtros ativos.
- Contador "Salvos" conta so favoritos que ainda existem.
- Busca ignora acentos ("calculo" acha "Calculo") e acha "doacao".
- Apos publicar um anuncio, os filtros sao limpos e a pagina sobe ao
  topo (antes o anuncio novo podia ficar escondido por um filtro).
- Codigo morto removido: imports/props nao usados, FilterState antigo
  (maxPrice, onlyMyListings), props nao usadas do Header.
- index.html: titulo "UniDesapego UNIFOR" e lang="pt-BR"
  (antes: "My Google AI Studio App", lang="en").
- Script "clean" agora funciona no Windows (usava rm -rf).
